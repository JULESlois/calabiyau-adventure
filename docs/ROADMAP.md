### 新地形如何接入(1.1–1.4 已验证的做法,后续沿用)

运行时的 `PlayState.tileAt()` 本来就把动态 tile 折回基础碰撞类型(极性弦膜→弦膜/空、
隐藏平台→实体/空)。四种新地形全部挂在同一处折叠:`@`→实体/空、`!`→单向/空、`:`→实体。
**因此 `rectHitsSolid` / `hasGroundAt` / 玩家物理一行未改。**
`check-maps.ts` 用同一招:静态校验前先把新 tile 折成别名(`@`/`:`→实体、`!`→单向、`;`→尖刺),
既有规则一条都不必重写,只需新增该地形自己的规则。**加第五种地形时请先走这条缝。**

### 1.4 冰面 `:` —— S —— ✅ 已完成

- 低摩擦地表:加速度 ×0.35、无输入滑行。
- 为后续 issue #39(坚冰滑轨)预留地基。

**更正原计划的判断**:原文写「constants 已集中,摩擦分支好做」。实际上**没有摩擦系数**,
`constants.ts` 里也从来没有过 —— 减速根本不是独立的项。`Player.ts` 的水平移动只有一个
`accel`(地面 `RUN_ACCEL` / 空中 `AIR_ACCEL`),有输入时 `approach(vx, 目标, accel*dt)`,
无输入时 `approach(vx, 0, accel*dt)`,**两个方向共用它**。
所以把 `accel` 乘以 0.35 会同时得到"推不动"与"刹不住" —— 正是冰的手感。
结论:×0.35 的处方正确,但理由不是"常量集中",而是"加减速本来就是同一个量",
改动落在单独一行。后续任何想改地面手感的项都应先读这一处,别去找不存在的摩擦系数。

## Phase 2 · 对话系统 + 潮汐游园(城镇)

### 2.0 先抽出可交互物注册表 —— S,**2.1 的前置** —— ✅ 已完成

原路线图在 2.1 写「NPC 走现有 interactables 管线」。**核对代码后发现没有这样一条管线。**
实际情况是 `PlayState` 里三份手工维护、必须彼此对齐的链:

- `updateInteractables()`(`PlayState.ts` ~1002 行):一串就近判定的 `if`,每个各带一个 `nearX` 布尔
- `interactionPromptLabel()`(~2122 行):另一串手排优先级
- `interactionPromptAnchor()`(~2133 行):再一串,顺序必须与上面一致 ——
  代码里那句注释「优先级与 updateInteractables 的检测顺序一致」就是这层耦合的自白

**照现状加一个 NPC 要改 PlayState 三处**;2.4 的名册是 4 个 NPC。
Phase 2 会把上一轮重构刚从 `PlayState` 抽走的体量(2595 → 2203 行)重新灌回去。

所以先做这一步:把可交互物抽成一张注册表 —— `{ id, rect(), label, anchor(), onInteract() }`,
`updateInteractables()` 退化为遍历,提示文字与锚点从同一条记录里取(三份链合成一份数据)。
信标/商店/祭坛/香奈美/捷径拉杆按原有优先级注册进去,行为不变,现有测试即回归。

**这一项做完,2.1 的 NPC 才真的只是"注册一条记录"。**代价是 S,省下的是 Phase 2 全程。

**落地记录**:新增 `Interactable` 类型(`id` / `zone` / `label` / `anchor` / `interact()`),
三串手排 if 链合成一个 `collectInteractables()`,`updateInteractables()` 退化为
"取第一个重叠条目"。六个 `nearXxx` 字段合并成单个 `activeInteractable` ——
**提示与行为现在物理上不可能分叉**,因为它们读的是同一条记录。

**核对时发现原文低估了问题**:那句「优先级与 updateInteractables 的检测顺序一致」的注释
**当时已经不成立**。检测顺序是 拉杆→极性→信标→祭坛→香奈美→商人,
提示顺序却是 信标→拉杆→极性→……。两个区域一旦重叠,提示会写「休息」而按下去开的是闸门。
更糟的是原实现里多个 `nearXxx` 可以**同时**为真(每段只 `break` 自己的循环、继续往下跑),
所以这不是理论风险。现已统一为检测顺序(以真正会发生的事为准,让界面说实话)。

新增 `tests/interactables.test.ts`(9 项),其中「提示永远描述真正会触发的那一条」
与「锚点必须落在自己的触发范围内」两条,守的就是这次修掉的两类分叉。
现有 131 项测试一条未改即全绿,可确认是行为等价重构。

## 美术 · 地形材质与图底分离(已完成)

**起因**:实测六区调色板后发现,`tileBase` 的饱和度在六区之间只差 13 个点(16%–29%),
而 `accent` 差 56 个点 —— **点缀色很丰富,材料本身几乎没有变化**。
再核对绘制代码:实体地形的 `T_SOLID` 分支全游戏只有一段,不含任何区域判断。
也就是说地面(每一帧占满下半屏的东西)是**同一种砖的六种配色**,
这正是路线图里那句「全石头科技」的可量化形态。

- **`render/tileStyles.ts`**:六种砌法 —— 海滨乱石砌(课高不齐 + 海蚀麻点 + 啃缺的顶沿)、
  沉潮湿方石(水渍拖尾 + 苔痕 + 顶沿水滴)、研究区铆接板(板缝 + 四角铆钉 + 顶面导光条)、
  圣堂细琢条石(细缝 + 斜凿纹 + 檐口齿饰)、天穹多孔轻石、机库焊接钢板(焊缝 + 锈斑 + 警戒斜纹)。
  颜色仍全部来自 `LevelTheme`,调色与调材质互不干扰。
- **跨区过渡**:材质无法插值,因此在过渡房**正中一次换过去** ——
  颜色连续渐变、砌法在中线突变,反而给了"已经过界"一个明确的节拍。
- **装饰噪点掺入房间散列**:原本只由世界坐标决定,竖向堆叠的房间装饰完全重复。

### 图底分离:一次被自己的度量骗过的修复

天穹区地形与近景层几乎同亮,玩家看不清自己站在哪里。修完材质后**重新量渲染结果**,
才发现问题比调色板显示的更普遍:

| 区域 | 调色板差 | 实测渲染差 | 侵蚀比 |
|---|---|---|---|
| 海滨 | 18.4 | 9.1 | 0.49 |
| 沉潮 | 15.6 | 12.8 | 0.82 |
| 研究区 | 11.5 | 11.9 | 1.03 |
| 圣堂 | 20.5 | 9.2 | 0.45 |
| 天穹(修复前) | 3.9 | **0.2** | — |
| 机库 | 11.1 | 9.3 | 0.84 |

**教训一:调色板里的底色不完全等于画出来的样子。**
所以 check-maps 的静态检查只是**下限**(现设 11),
权威数值由 `npm run qa:tiles` 直接量渲染结果给出。

**教训二(更重要):量测工具本身也要被怀疑一次。**
上表「侵蚀比 0.45–0.49」是**错的**。真实比值是 0.85–1.11(乱石砌略降,焊接钢板略升)。
错误来自 qa 工具自己:`MiniCtx` 的 `save/restore` 只快照了平移,没快照 `globalAlpha`,
而烛火的画法是 save → 压低 alpha → restore ——
于是**每个房间里第一支烛火之后画的所有东西都被压暗**,量出来的分离度自然偏低。
这个 bug 是在给城镇渲图时发现的:一整条木栈道只有左边四格是亮的。
修好后全部重测,才得到上面的真实区间。
天穹改为**深色地形衬亮天空**(与其它区相反,但那一区天空本来就亮),分离度 0.2 → 31.7。

新增规则:六区材质不得重复;调色板分离不得低于 11。
新增 `tests/tile-art.test.ts` 12 项,其中「任何材质压暗自身不得超过一半」
守的就是"静态下限会被材质吃穿"这件事。

### 天际线:研究区与机库不再借用别人的骨架

原先 `levelId === 2 || levelId === 5` 共走一条分支 —— 研究区用的是圣堂的哥特拱窗 + 石柱,
只额外叠了培养仓;机库用的是王座厅的立柱,只把垂旗换成吊轨。
**从背景看,那是同一栋建筑。** 代码注释「沿用原本建筑骨架」「保留高大立柱」就是自陈。

- **研究区**:新增 `rack`(机柜阵列,带按柜位缓慢闪烁的指示灯)与 `dish`(缓慢摆动的抛物面天线),
  与培养仓/输能管线组成自己的天际线。
- **机库**:新增 `tower`(发射塔桁架,交叉斜撑 + 顶部航警灯),取代礼堂立柱 ——
  天际线从"宫殿"变成"工地"。

### 大气:第三个身份维度

`LevelTheme.atmosphere` 描述雾浓度、雾带厚度、微粒(种类/数量/尺寸/速度/摆幅)与斜向光束。
原先六区共用一套处理、只差颜色,且光束写死只给海滨与天穹。现在:

| 区域 | 雾浓度 | 微粒 | 光束 |
|---|---|---|---|
| 海滨 | 1.0 | 余烬上升 | 暖 |
| 沉潮 | **1.9**(浑浊) | 气泡上升(空心 2px) | 无 |
| 研究区 | 0.7 | 浮尘悬浮 | 无 |
| 圣堂 | 1.2 | 光尘缓升 | 冷 |
| 天穹 | **0.45**(稀薄) | 落雪下沉 | 冷 |
| 机库 | 1.6(烟) | 煤灰上升(2px) | 无 |

浓雾(>1.3)会补画第二层雾带,做出"看不透"的厚度。
大气与材质一样在过渡房正中一次切换 —— 空气的浓稠程度没有中间态。

新增校验:六区大气不得完全相同。测试增至 18 项(本文件)。

## M0 · 闭合回路(已完成)—— 从 Phase 4 提前

**为什么插队**:Phase 4 是全文档最便宜的一批(全是 S),却排在最后。
而实测数据显示,游戏缺的不是内容,是**奖励曲线在半程就断了**:

| | 世界里有 | 原本仍有作用 | 失效 |
|---|---|---|---|
| 弦晶 | 80 | 42(末档里程碑) | **47.5%** |
| 晶尘 | 单程约 780 | 260(全店) | **67%**,且敌人随房间重入刷新,供给实际无上限 |

结算屏只报一个弦晶数,7 秒后**强制**弹回标题 —— 玩家跑遍全世界拿到的遗珍、捷径、
房间、可选 Boss 一概不被提及。系统都是完整的,断掉的是回报。因此先闭合这条主线,
再让 Phase 1 余项与 Phase 2 的城镇长在一条完整的脊梁上。

- **弦晶曲线延长**:里程碑加到 54 / 68,末档覆盖 68/80(85%)。
  末档刻意不设在 80 —— 最后一档不该要求完美收集,留 12 枚容错。
- **晶尘去处**:一次性商品 4 → 6 条(260 → 460),另加**价格递增的可重复条目**
  「弦芯熔铸」(6 次共 720)。一次性商品的总价有限,而晶尘可再生,
  因此**必须**有一个填不满的去处,否则它在中盘必然退化成噪音。
- **通关结算屏**:弦晶/遗珍/芯片/捷径/房间/首领六项分栏 + 总完成度,
  「继续探索」为默认选项,不再自动弹回标题。
  总分取**各项比例的平均**而非"总获得/总数量" —— 后者会让 80 项的弦晶淹没 4 项的 Boss。
- **平衡巡检**:敌人 133 → 156;四种最新敌种(弦蛭/迫击晶/逆弦犬/镜弦猎兵)
  占比 13.5% → 23.1%,巡逻机 8 → 13。镜弦猎兵原本全程只出现 3 次,
  玩家刚学会读它的招式游戏就结束了。
- **新增 check-maps 规则**:末档里程碑必须落在弦晶总量的 80%–92%;
  商店必须存在可重复条目;一次性商品总价不得低于单程晶尘产出的一半。
  **世界一扩张,收集品就涨,而里程碑和价格是写死的常量 —— 这条曲线不设防就会再断一次。**
- 测试 102 → 121(+19)。
